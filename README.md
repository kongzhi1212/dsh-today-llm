# Today 模型

把本机已登录的 **Today 桌面端**账号接到 DeepSeek Harness，作为一个名为 `today` 的模型提供方。

> **这不是一个普通的 API 接入插件，请先读完这一段再安装。**
>
> 1. **它不是真正的模型通道。** Today 没有 OpenAI 兼容的补全接口，每个请求是发给 Today 自己的 agent 执行的。因此：回复**不是逐字流式**的；agent 自身的人格与长期记忆仍会塑造回答（提示词要求它忽略，但无法完全覆盖）；它**自己的工具无法关闭**，可能自行读文件或联网——任何「我做了某事」的回答都不能当作事实。
> 2. **模型选择是账号级的。** Today 按账号保存一个当前模型，消息接口忽略任何按请求的模型字段。所以在 DSH 里选模型会改动你整个 Today 账号，包括手机上那一份。默认并发为 1，是为了避免两个不同模型的请求互相改写对方正在等待的会话。
> 3. **真实消耗配额。** 插件不绕过计费，每次请求都按 Today 自己的规则扣你的额度。
> 4. **依赖上游实现细节。** 它读取 Today 桌面端的加密凭据并调用其内部接口。上游一旦调整，插件可能失效。
>
> 这是独立的互操作性适配工具，**与 Today 官方无关**，未获其授权或背书。

## 它做什么

- 从 Today 自己的模型目录读取**这个账号**可用的模型，选择器里出现的正是这些模型，并带上 Today 收取的用量倍率（如 `4×`）。
- 每隔一段时间重读目录，账号侧的变化无需重启即可反映到选择器。
- 在 DSH 里选中某个模型后，每次请求前把该选择同步到 Today 账号，因此选的就是跑的。
- 在**设置 → Today** 里提供完整的一页：账号、套餐用量、模型（可逐个显示/隐藏并设置上下文窗口）、可编辑的插件设置、最近任务、最新日记。

## 安装

```bash
# 在 DSH 里把本目录作为本地 bundle 安装
dsh plugin add /path/to/dsh-today-llm
```

或者用 DSH 的**插件 → 添加插件**指向本目录。安装前先 `pnpm install` 拉取唯一的那一个依赖（`@deepseek-ai/schemastery`）。

前提：本机已登录 Today 桌面端。插件只读它的凭据文件，绝不写入。


## 设置页

设置面板左侧导航里会多出「Today」一项，与「账号与余额 / 通用设置 / 模型 / 插件」并列。

### 只读状态

| 区域 | 内容 | 来源 |
| --- | --- | --- |
| 账号 | 登录标识、凭据目录 | 本地凭据文件 |
| 套餐与用量 | 套餐级别、剩余百分比、重置时间、服务状态 | `/v1/pricing/status` |
| 最近任务 | 最近 8 条后台任务及其状态 | `/v1/tasks` |
| 最新日记 | 当日日记标题与摘要 | `/v1/diaries` |

### 可编辑设置

改动是**草稿式**的：不动 `保存` 就不写盘。保存走宿主的 `ctx.settings.update`，它负责校验、保留文件里其它内容，并重启插件使新值生效。

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 单次超时 | 300 秒 | 等待一次 Today 回复的上限 |
| 轮询间隔 | 700 毫秒 | 等待期间重读会话的频率 |
| 模型刷新 | 600 秒 | 重读模型目录的间隔，`0` 表示不刷新 |
| 默认上下文窗口 | 200000 | 未单独设置的模型用它 |
| 并发请求数 | 1 | 见下方风险提示 |
| 严格 JSON 协议 | 开 | 关闭后回复更自然，但**工具调用会失效** |
| 上报估算用量 | 开 | 关闭后不报 token 数 |

**每个模型**还有两列：显示/隐藏开关，以及可选的自定义上下文窗口。

### 数据通道

页面走宿主自己的 HTTP 路由，与其它宿主路由共用同一枚启动 cookie：

- `GET /dsh-today-llm/status` — 状态快照
- `POST /dsh-today-llm/config` — 配置改写（只接受页面拥有的字段）

路径**必须**在 `/api` 之外：连接层用前缀路由独占了整个 `/api`，注册在那里的资源永远不会被匹配到。

## 并发设置的风险

Today 的模型选择按账号保存。并发设为 1 时，「设定模型 → 发起对话 → 等到回复」是原子的；设成 2 以上，两个不同模型的请求可能互相改写对方正在等待的那个会话。同一模型的两个请求不受影响，所以如果你的用法固定，调高是安全的——但这需要你自己确认。


## 使用前提

本机必须已登录 Today 桌面端。插件读取 `%APPDATA%\Today CN`（macOS 为 `~/Library/Application Support/Today CN`，Linux 为 `$XDG_CONFIG_HOME/Today CN`）下的登录凭据：

- `Local State` 里的 `os_crypt.encrypted_key` 由系统凭据库（Windows DPAPI / macOS Keychain / Linux libsecret）保护，插件只做解包。
- 真正的会话记录在 `account-credentials.slot-*`，用 Chromium 的 `v10` 信封加密。

这一切都是**只读**的：Today 桌面端的文件一个字节都不会被改动。

## 必须知道的限制

| 限制 | 说明 |
| --- | --- |
| 不是逐字流式 | Today 没有补全接口，回复完成后一次性写入会话。适配器据此发出一个完整文本块。 |
| 受 agent 人格影响 | 请求交给 Today 自己的 agent，它的人格与长期记忆仍会塑造回答。适配器会显式要求它忽略这些，但无法完全覆盖。 |
| 自有工具无法关闭 | 该 agent 有自己的文件、命令与连接器工具，接口无法禁用。提示词要求它改为请求 DSH 的工具，但不能保证。 |
| 模型选择是账号级 | Today 按账号保存一个当前模型，消息接口忽略任何按请求的模型字段。因此插件默认把「设定模型 → 发起对话 → 等到回复」整段串行化，不同模型的并发请求会排队而不是互相覆盖。并发数可在设置页调整。 |
| 用量是估算 | Today 不返回 token 用量，计数按字符数估算（中日韩字符与拉丁字符分别折算）。设置页的套餐用量则是 Today 的真实读数。 |
| 会话是隔离的 | 每个请求都在一个新建的 `new_task` 会话里跑，不会污染 Today 主对话，也不携带你的聊天历史。 |

## 配置

全部字段都在设置页可改；也可以直接写在 `cordis.patch.yml` 的行上。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `timeoutMs` | `300000` | 单次请求等待上限。 |
| `pollIntervalMs` | `700` | 等待期间重读会话的间隔。 |
| `refreshModelsMs` | `600000` | 重读模型目录的间隔；`0` 表示不重读。 |
| `defaultContextWindow` | `200000` | 未单独设置的模型报告的上下文窗口。 |
| `maxConcurrency` | `1` | 并发请求数，1~8。 |
| `strictProtocol` | `true` | 是否强制 JSON 回复；关闭后工具调用失效。 |
| `reportUsage` | `true` | 是否上报估算的 token 用量。 |
| `models` | `{}` | 按模型 id 覆盖：`{ "glm-5.3": { "hidden": true, "contextWindow": 500000 } }` |

## 停用

在「插件」里停用或卸载即移除 `today` provider，Today 账号与桌面端登入状态都不受影响。

## 免责

本插件是独立的互操作性适配工具，与 Today 官方无关。它不绕过计费：每一次请求都按 Today 自己的规则真实消耗你的账号配额。上游接口调整可能导致插件失效，届时需要跟着更新。
