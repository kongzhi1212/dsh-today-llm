# Today 模型

把本机已登录的 **Today 桌面端**账号接到 DeepSeek Harness，作为一个名为 `today` 的模型提供方。接进来的是这个账号在 Today 里能用的所有模型——**GLM、Kimi、Qwen、MiniMax、DeepSeek** 等，不需要另外充值或建号。

> **这不是一个普通的 API 接入插件，请先读完这一段再安装。**
>
> 1. **它不是真正的模型通道。** Today 没有 OpenAI 兼容的补全接口，每个请求是发给 Today 自己的 agent 执行的。因此：回复**不是逐字流式**的；agent 自身的人格与长期记忆仍会塑造回答（提示词要求它忽略，但无法完全覆盖）；它**自己的工具无法关闭**，可能自行读文件或联网——任何「我做了某事」的回答都不能当作事实。
> 2. **模型选择是账号级的。** Today 按账号保存一个当前模型，消息接口忽略任何按请求的模型字段。所以在 DSH 里选模型会改动你整个 Today 账号，包括手机上那一份。默认并发为 1，是为了避免两个不同模型的请求互相改写对方正在等待的会话。
> 3. **真实消耗配额。** 插件不绕过计费，每次请求都按 Today 自己的规则扣你的额度。
> 4. **依赖上游实现细节。** 它读取 Today 桌面端的加密凭据并调用其内部接口。上游一旦调整，插件可能失效。
>
> 这是独立的互操作性适配工具，**与 Today 官方无关**，未获其授权或背书。

## 能用哪些模型

选择器里的模型来自**你自己号上**的 Today 目录，不是写死的清单。这些是当前实测接进来的：

| 厂商 | 模型 | 用量倍率 |
| --- | --- | --- |
| DeepSeek | DeepSeek V4.1 Flash | `1×` |
| MiniMax | MiniMax M3.1 Flash | `1×` |
| 智谱 | GLM 5.3 Flash | `1×` |
| 智谱 | GLM 5.3 | `4×` |
| 阿里 | Qwen3.8 Max | `5×` |
| 月之暗面 | Kimi K3.1 Pro | `8×` |
| 月之暗面 | Kimi K3.1 Pro Highspeed | `16×` |

倍率是 Today 自己收的费率，插件只做展示。目录变了选择器会自动跟着变，不需要改插件——所以上表只是实测快照，不是上限。

## 它做什么

- 从 Today 自己的模型目录读取**这个账号**可用的模型，选择器里出现的正是这些模型，并带上 Today 收取的用量倍率（如 `4×`）。
- 每隔一段时间重读目录，账号侧的变化无需重启即可反映到选择器。
- 在 DSH 里选中某个模型后，每次请求前把该选择同步到 Today 账号，因此选的就是跑的。
- 在**设置 → Today** 里提供完整的一页：账号、套餐用量、模型（可逐个显示/隐藏并设置上下文窗口）、可编辑的插件设置、最近任务、最新日记。

## 安装

四条路，按你的情况挑一条。

**① Windows 双击（不用命令行）**

从 [Releases](https://github.com/kongzhi1212/dsh-today-llm/releases) 下载 `.tgz` 和 `install-windows.bat` 放进同一个文件夹，双击 bat。它会自己找到 DSH 的安装位置并装进 `desktop` profile。

**② 离线包（任意平台）**

```bash
dsh plugin --profile desktop add ./dsh-today-llm-1.5.0.tgz
```

**③ npm（发布后可用）**

```bash
dsh plugin --profile desktop add dsh-today-llm
```

**④ 从源码（开发用）**

```bash
pnpm install
dsh plugin --profile desktop add /path/to/dsh-today-llm
```

或者用 DSH 的**插件 → 添加插件**指向本目录。

> 直接把目录**复制**到另一台机器是不行的：插件依赖 `@deepseek-ai/schemastery`，需要一个真实的 `node_modules`。用 `.tgz`，包管理器会把依赖一起装好。

前提：本机已登录 Today 桌面端。插件只读它的凭据文件，绝不写入。

### 排障

一条命令看完凭据状态、服务区域、令牌刷新、模型目录、套餐用量：

```bash
dsh-today-llm doctor      # 或 npx dsh-today-llm doctor / node bin/doctor.js
```

退出码 0 表示可用，1 表示有致命问题。它只做只读调用，不会改动任何东西。

| 设置项 | 默认 | 说明 |
| --- | --- | --- |

| 单次超时 | 300 秒 | 等待一次 Today 回复的上限 |
| 轮询间隔 | 700 毫秒 | 回退到轮询时重读会话的频率 |
| 模型刷新 | 600 秒 | 重读模型目录的间隔，`0` 表示不刷新 |

| 推送事件流 | 开 | 用 WebSocket 接收回复；连不上时自动回退轮询 |
| 上报估算用量 | 开 | 关闭后不报 token 数 |
| 恢复账号原模型 | 开 | 每轮结束后把 Today 账号的模型改回去 |

| OpenAI 端点地址 | 127.0.0.1 | 监听地址，默认只对本机 |

**每个模型**还有：显示/隐藏开关、「跟随默认」勾选，以及取消该勾选后可填的自定义上下文窗口。目录里还有一颗「隐藏收费模型」按钮，一次把所有倍率大于 1× 的模型收起来。

### 接收回复的方式

默认走 Today 的推送通道，而不是轮询：

```
POST /registry/devices → POST /ws-ticket → wss://.../ws?ticket=...
  → device.hello → chat.message_ready.v2 事件 → isFinal 收尾
```

这样 Today 一写出回复就能拿到，比每 700 毫秒问一次更快也更省请求。握手失败会自动退回 HTTP 轮询；连续失败 3 次后事件流会**暂停 5 分钟**，冷却结束自动重试，冷却期间照常轮询——**socket 出问题不会让你拿不到答案**。设置页的诊断区会显示当前是「已启用 / 已暂停（剩余秒数）/ 你已关闭」三者中的哪一种。

想强制走轮询，把「推送事件流」关掉即可。

### 新模型会自动出现

Today 上架新模型后，插件下一次刷新目录（默认每 10 分钟）会检测到变化并发出宿主的 `llm/models-updated` 事件，模型选择器随即重新加载——**不需要重启 DSH**。只有目录内容真的变了才会发事件，所以稳定的目录不会每轮都打扰订阅者。


### 数据通道

页面走宿主自己的 HTTP 路由：

- `GET /dsh-today-llm/status` — 状态快照
- `POST /dsh-today-llm/config` — 配置改写（只接受页面拥有的字段）
- `POST /dsh-today-llm/probe` — 单个模型的连通性测试

路径**必须**在 `/api` 之外：连接层用前缀路由独占了整个 `/api`，注册在那里的资源永远不会被匹配到。

三个路由都用 `handler`（不是 `resource`）：宿主的资源型路由只接受 GET/HEAD，对其余方法直接返回 405，那样两个 POST 端点在实际 HTTP 下根本走不通。每个路由先过宿主的 `connection.admit`，也就是 `/api` 用的同一道 Host/Origin 白名单加启动 cookie 校验——未认证请求会被拒。

### 诊断

设置页底部是一张诊断表，记录本次运行最近 20 次请求：

| 列 | 内容 |
| --- | --- |
| 请求 | 模型 · 走的 socket 还是轮询 · 耗时 |
| 结果 | `text` / `tool-call` / 错误码 |
| 错误详情 | 上游原文（截断） |

外加事件流状态（是否启用、连续失败次数），以及**逐模型测试**按钮。测试会发一条真实请求，所以每测一次都消耗一次账号额度——页面在按钮上方写明了这一点，也不会定时触发。


## 模型选择对账号的影响

这是这个插件最需要知道的一件事：**Today 的模型选择是账号级的**，不是按会话的。在 DSH 里选一个模型，你手机上那份 Today 的当前模型也会跟着变。

插件默认做了缓解：**每轮开始前记下账号原来的模型，结束后恢复回去**（设置页「每轮结束后恢复账号原模型」，默认开）。这样插件的改动只在你使用 DSH 的那几十秒里存在。

关掉它会少两次选择写入、略快一点，但你的账号模型会停在 DSH 选的那个上。

两个边界要知道：

- 恢复是**尽力而为**。恢复调用失败不会让这一轮失败（答案已经拿到了），但账号会停在插件设的模型上。
- 同时开**两个 DSH 实例**时它们互不协调，谁后恢复谁赢。单实例内的并发由队列保证有序。

## OpenAI 兼容端点（可选）

除了 DSH，这个代理还能给**只认 OpenAI 协议**的工具用（编辑器插件、终端助手），让它们共用同一份 Today 额度。

在设置页把 `servePort` 设成一个端口（默认 `0` 关闭）后启动：

```bash
curl http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer <serveToken>" \
  -H "Content-Type: application/json" \
  -d '{"model":"glm-5.3","messages":[{"role":"user","content":"你好"}]}'
```

也支持 `GET /v1/models`。写了 `serveToken` 就要求 Bearer 头，留空则接受本机任何调用者。默认只监听 `127.0.0.1`。

**能力有限，请按实际宣传**：没有 token 级流式、不支持 function calling、不支持 embeddings。工具调用会被转成一句说明文字返回，而不是丢掉。别指望它完全等价于 OpenAI。

## 并发设置的风险

Today 的模型选择按账号保存。并发设为 1 时，「设定模型 → 发起对话 → 等到回复」是原子的；设成 2 以上，两个不同模型的请求可能互相改写对方正在等待的那个会话。同一模型的两个请求不受影响，所以如果你的用法固定，调高是安全的——但这需要你自己确认。

并发**不是排队超时**：请求按到达顺序拿锁，超出并发的会等着而不是被拒绝。


## 使用前提

本机必须已登录 Today 桌面端。插件读取 `%APPDATA%\Today CN`（macOS 为 `~/Library/Application Support/Today CN`，Linux 为 `$XDG_CONFIG_HOME/Today CN`）下的登录凭据。

Today 有**两个独立部署**，账号体系不互通：

| 区域 | 用户数据目录 | API / 认证域名 |
| --- | --- | --- |
| 中国大陆（`cn`） | `Today CN` | `api.todayai.cn` / `auth.todayai.cn` |
| 国际版（`global`） | `Today` | `api.today.ai` / `auth.today.ai` |

`region` 设为 `auto`（默认）时两个都探测，先 CN 后 global，设置页会显示实际命中的区域。

凭据有两种信封，插件按文件头自动识别：

- **`v10`** —— Chromium safeStorage。密钥在 `Local State` 的 `os_crypt.encrypted_key`，由系统凭据库（Windows DPAPI / macOS Keychain / Linux libsecret）保护。
- **`TDK1`** —— Today 自己的信封，密钥在 macOS 钥匙串条目 `ai.today.desktop.account-credentials` 里。macOS 版用它代替 safeStorage。

真正的会话记录在 `account-credentials.slot-*`。这一切都是**只读**的：Today 桌面端的文件一个字节都不会被改动。

## 开发

```bash
pnpm install
pnpm test    # node --test，34 项
pnpm check   # 逐个文件的语法检查
```

测试只覆盖纯逻辑：协议解析、信封布局、请求头与错误码映射、并发锁。它们**不联网、不碰真实凭据**——凭据相关的用例把探测路径重定向到临时空目录，所以失败信息里不会出现你的账号。

Node 要求是 `>=22.4.0`，不是因为用了什么新语法，而是 `globalThis.WebSocket` 从 Node 22.4 起才稳定。低于这个版本插件仍能跑，但事件流那条路会静默退回轮询。

## 必须知道的限制

| 限制 | 说明 |
| --- | --- |
| 不是逐字流式 | Today 没有补全接口。它把正在生成的回复以「完整快照」推进事件流，插件据此算差量，所以能看到进度，但仍是整段而不是逐 token。 |
| 受 agent 人格影响 | 请求交给 Today 自己的 agent，它的人格与长期记忆仍会塑造回答。适配器会显式要求它忽略这些，但无法完全覆盖。 |
| 自有工具无法关闭 | 该 agent 有自己的文件、命令与连接器工具，接口无法禁用。提示词要求它改为请求 DSH 的工具，但不能保证。 |
| 模型选择是账号级 | Today 按账号保存一个当前模型，消息接口忽略任何按请求的模型字段。因此插件默认把「设定模型 → 发起对话 → 等到回复」整段串行化，不同模型的并发请求会排队而不是互相覆盖。并发数可在设置页调整。 |
| 用量是估算 | Today 不返回 token 用量，计数按字符数估算（中日韩字符与拉丁字符分别折算）。设置页的套餐用量则是 Today 的真实读数。 |
| 上下文窗口是假设值 | **Today 的接口不返回上下文长度**（目录里只有名称、用量倍率、发布方）。`defaultContextWindow` 是一个保守假设，不是实测值；某模型实际能吃多少 token，只能靠 `models` 里的单独覆盖来调。 |
| 会话是隔离的 | 每个请求都在一个新建的 `new_task` 会话里跑，不会污染 Today 主对话，也不携带你的聊天历史。 |

## 配置

全部字段都在设置页可改；也可以直接写在 `cordis.patch.yml` 的行上。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `timeoutMs` | `300000` | 单次请求等待上限。 |
| `pollIntervalMs` | `700` | 回退到轮询时重读会话的间隔。 |
| `refreshModelsMs` | `600000` | 重读模型目录的间隔；`0` 表示不重读。 |
| `defaultContextWindow` | `200000` | 未单独设置的模型报告的上下文窗口。 |
| `maxConcurrency` | `1` | 并发请求数，1~8。 |
| `strictProtocol` | `true` | 是否强制 JSON 回复；关闭后工具调用失效。 |
| `useSocket` | `true` | 用推送事件流接收回复；关闭则一律轮询。 |
| `reportUsage` | `true` | 是否上报估算的 token 用量。 |
| `models` | `{}` | 按模型 id 覆盖：`{ "glm-5.3": { "hidden": true, "contextWindow": 500000 } }` |
| `deviceId` | 派生 | Today 登记的机器标识。留空则由「主机 + 用户 + profile」哈希出稳定值。 |
| `region` | `auto` | `auto` / `cn` / `global`。两个区域是**独立账号体系**，域名也不同。 |
| `restoreModelAfterTurn` | `true` | 每轮结束后恢复账号原模型。 |
| `streamChunkChars` | `48` | 伪流式分片宽度；`0` 关闭分片。 |
| `streamChunkDelayMs` | `12` | 分片间隔上限，受每轮预算约束。 |
| `servePort` | `0` | OpenAI 兼容端点端口，`0` 关闭。 |
| `serveHost` | `127.0.0.1` | 端点监听地址。 |
| `serveToken` | `""` | 端点要求的 Bearer 令牌，空则不限。 |

## 停用

在「插件」里停用或卸载即移除 `today` provider，Today 账号与桌面端登入状态都不受影响。
